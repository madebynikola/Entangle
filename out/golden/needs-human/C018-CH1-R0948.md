## Automated System Extract to ARXML Generation via the DaVinci Configurator API

**Company:** DriveLogic Vojvodina d.o.o. works in automotive and mobility software. [C018] Challenge C018-CH1.  
**Researcher:** Mirjana Vidaković is a Full Professor in the Department of Computing and Control Engineering, Faculty of Technical Sciences. [R0948]  
**Format:** joint project, one page.

### The problem
DriveLogic manually generates approximately 3,200 AUTOSAR software component configuration files per project, occupying two senior engineers for three weeks. [C018-CH1] The bottleneck makes the company uncompetitive on price-sensitive bids. [C018-CH1] The mapping logic between the customer-provided System Extract and the final ARXML configuration set must be automated, and the output must be a reviewable first-draft configuration set that engineers check and correct. [C018-CH1]

### Research questions
1. Can a transformation chain reading a System Extract and writing DaVinci API calls generate a complete, rule-conformant ARXML SWC configuration draft within one working day? Measured as end-to-end wall-clock time on the two most recent project baselines, with conformance checked against the company's existing hand-authored ARXML sets.
2. How many manual corrections do engineers need to make to the generated first-draft, compared with starting from scratch? Measured as the count of post-generation edits logged during review of the generated set against the hand-authored baseline on the same two projects.

### Approach
- Parse the customer-provided System Extract into an intermediate model using the AUTOSAR metamodel concepts from the researcher's SWC-descriptor work, capturing port interfaces, runnables, and component topology needed to drive DaVinci API calls.
- Apply model-transformation rules—drawing on ATL and QVT-O patterns from the researcher's comparative transformation work—to map System Extract elements to ARXML SWC configuration constructs, with explicit guard predicates that route exception cases to a review log rather than failing silently.
- Generate ARXML files and DaVinci API invocations using Acceleo or Xpand templates, following the template-based generation patterns from the researcher's RTE-stub and Adaptive-Platform work, with ARXML-aware diffing applied after generation so engineers see only the delta against any prior baseline.
- Validate the generated set incrementally: change-impact analysis drawn from the researcher's incremental-generation work limits regeneration to components affected by a System Extract update, keeping subsequent runs well under one working day even as projects evolve.

### First six months
- Week 1–2: The company engineer transfers two completed project System Extract files and their corresponding hand-authored ARXML sets to the university under a signed NDA; Vidaković registers a master's student on the project.
- Month 1–2: The master's student and company engineer jointly document the System Extract schema, annotating each element with its target ARXML construct; Vidaković reviews and signs off the mapping specification.
- Month 2–3: The master's student builds the parser and intermediate metamodel; the company engineer tests it against both reference projects and records any schema gaps for the next iteration.
- Month 4–6: The master's student implements transformation rules and generation templates targeting the DaVinci Configurator API; the company engineer integrates the generator into the team's workflow and logs review edits on one live project to establish the correction baseline.

### Why this pair
DriveLogic holds the ground-truth data—two completed project baselines with System Extract inputs and hand-authored ARXML outputs—and the DaVinci API access that any solution must target, but the transformation and generation methods needed to automate the mapping are not part of the company's engineering practice. Vidaković brings published methods for AUTOSAR model transformation, template-based ARXML generation, incremental regeneration, and ARXML-aware diffing, but has no access to the company's proprietary System Extract format or project baselines.
