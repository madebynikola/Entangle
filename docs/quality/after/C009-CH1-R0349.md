## Morphology-Aware, Script-Robust Indexing to Cut LinguaBot's Query Miss Rate Below 5%

**Company:** LinguaBot d.o.o. works in conversational AI. [C009] Challenge C009-CH1.  
**Researcher:** Stefan Dragić is a Full Professor in the Department of Mathematics and Informatics, Faculty of Sciences. [R0349]  
**Format:** joint project, one page.

### The problem
LinguaBot's Elasticsearch pipeline misses 18% of queries in a 12,000-query sample from one bank client because Serbian inflectional forms (e.g. 'kartica', 'karticu', 'karticom') and Latin–Cyrillic script mixing cause token mismatches. [C009-CH1] The current synonym list and simple script-normalisation approaches do not scale as bank clients add new product terminology every quarter. [C009-CH1] The company targets a miss rate below 5% and has a budget of around 8,000 EUR with a six-month deadline. [C009-CH1]

### Research questions
1. Can a pipeline that combines phoneme-based script normalisation with morphological lemmatisation, integrated into the existing Elasticsearch index, reduce the miss rate from 18% to below 5%? Measured on the 12,000-query bank-client sample against the labelled query-response dataset.
2. Can the index be updated incrementally when new banking product terms are added, without full re-indexing, while keeping miss rate below 5%? Measured by running a quarterly-vocabulary simulation on a held-out set of new terms annotated by the company's linguists.

### Approach
- Apply phoneme-based token mapping from the script normalisation and canonicalisation work to collapse Latin and Cyrillic variants of each query token to a single canonical form before indexing and at query time.
- Integrate morphological analysis and stemming, following the approach from the Serbian IR work, to lemmatise inflected forms so that 'kartica', 'karticu' and 'karticom' map to the same index entry.
- Build the index using an inverted-index structure robust to script variation, adapted for the company's Elasticsearch setup; use incremental indexing for new terminology so that quarterly vocabulary additions do not require full re-indexing.
- Apply query expansion with cross-script matching at retrieval time to handle queries that mix scripts mid-token, then evaluate the full pipeline on the labelled 85,000-pair dataset with the 12,000-query bank-client sample as the primary test set.

### First six months
- Month 1: The company shares the 12,000-query bank-client sample and a representative slice of the 85,000-pair dataset with the master's student under a data-access agreement; Stefan Dragić and the company's linguists agree on the annotation schema for failure modes.
- Month 1–2: The master's student and the company's linguists jointly annotate a 2,000-query evaluation subset; Stefan Dragić reviews and finalises the gold-standard labels.
- Month 2–3: The master's student implements and tests the phoneme-based script normalisation layer on the evaluation set; the company's engineer connects it to the existing Elasticsearch and spaCy pipeline.
- Month 3–4: The master's student integrates morphological lemmatisation and runs the first end-to-end miss-rate measurement; results reviewed by Stefan Dragić and the company before moving to incremental indexing.
