## Script-Normalization and Morphological Query Expansion to Cut LinguaBot's 18% Search Miss Rate

**Company:** LinguaBot d.o.o. works in conversational AI. [C009] Challenge C009-CH1.  
**Researcher:** Stefan Dragić is a Full Professor in the Department of Mathematics and Informatics, Faculty of Sciences. [R0349]  
**Format:** joint project, one page.

### The problem
LinguaBot's knowledge-base search returns no useful result for about 18% of queries in a sample of 12,000. [C009-CH1] The miss rate is traced to morphological mismatch and Latin–Cyrillic script mixing in an Elasticsearch pipeline that currently uses only a Croatian-based stemmer. [C009-CH1] The Croatian-based stemmer misses Serbian-specific inflectional forms (e.g. 'kartica', 'karticu', 'karticom'). [C009-CH1] New product terminology arrives every quarter and must be incorporated without full re-indexing. [C009-CH1] The budget for tooling or data work is around 8,000 EUR. [C009-CH1] The solution must be testable within six months. [C009-CH1]

### Research questions
1. Can a script-normalization and morphological query-expansion layer, integrated into LinguaBot's Elasticsearch pipeline, reduce the miss rate from 18% to below 5%? Measured against the 12,000-query labelled sample, using the same relevance judgments the company currently applies, before and after deployment.
2. Can quarterly terminology additions be ingested without full re-indexing, with retrieval quality on new terms matching that on existing terms within 48 hours of ingestion? Measured on a held-out set of 500 queries per quarterly cycle against a manually verified answer set produced by the company's computational linguists.
3. What is the latency cost of the normalization and expansion layer in the production Python pipeline? Measured as median and 99th-percentile query response time under the observed load of approximately 140,000 sessions per month, with a target of no more than 50 ms added latency per query.

### Approach
- Audit the existing Elasticsearch analyzer chain using the 12,000-query labelled sample to classify miss types: script-mismatch misses versus morphological misses versus out-of-vocabulary misses. This directly applies the benchmark-corpus construction and graded relevance methodology from the researcher's prior work.
- Build a script-normalization module using the researcher's character-level neural transliteration approach for Serbian, handling loanwords and exception classes that deterministic rules miss. Plug it in as a custom Elasticsearch token filter in the Python pipeline.
- Implement morphological query expansion by generating inflectional variants for query terms using the phoneme-based canonicalization and transliteration-variant expansion methods from the researcher's publications on Serbian-language web and document search. Index expanded forms at query time rather than document time to avoid re-indexing on terminology updates.
- Evaluate the combined pipeline on the full 85,000-pair labelled dataset using precision, recall and miss rate, with inter-annotator agreement from the company's two computational linguists providing the ground-truth relevance labels. Apply the latency–accuracy trade-off analysis methods from the researcher's production deployment work.
- Deliver an incremental-ingestion procedure: when new client terminology arrives, add terms to the expansion lexicon and re-normalize only the new documents. Validate on the first quarterly cycle that falls within the project window.

### First six months
- Week 1–2: Sign data-processing agreement. LinguaBot exports the 12,000-query labelled sample and 10,000 representative knowledge-base documents. Researcher confirms receipt and sets up an isolated analysis environment.
- Week 3–4: Set up a shared test harness in LinguaBot's Python staging environment that measures miss rate and median query latency automatically on each pipeline change. Both sides agree on the definition of a 'miss' to be used throughout.
- Month 2: Complete the miss-type audit. Deliver a written report classifying misses as script-mismatch, morphological, or out-of-vocabulary, with counts. Both sides review and agree on priority order for the build.
- Month 3: Deliver a first script-normalization token filter built on the researcher's transliteration module, integrated into Elasticsearch staging. Run it against the held-out 500-query set. Log results to the shared harness.
- Month 4: Add the morphological query-expansion layer. The company's two computational linguists annotate a second 500-query held-out set for the expansion evaluation. Measure combined miss rate and latency.

### Why this pair
LinguaBot's miss rate is caused by exactly the two problems — script mixing and Serbian morphological mismatch — that Dragić has published on and built working prototypes for. The company has a large labelled dataset and a live pipeline but no researcher with the depth to redesign the analyzer chain; the researcher has the methods and open-source modules but no production pipeline, no labelled customer-support corpus, and no client relationships in the conversational-AI sector to validate a deployment. ### Agreed up front (proposed)
- Publication: results may be published after a 30-day review by LinguaBot. LinguaBot may request a delay of up to 60 additional days if a publication would reveal proprietary client data or query distributions. The researcher may publish methods and aggregate evaluation results; per-client data are excluded from any publication.
- Ownership of results: the trained normalization and expansion models, the Elasticsearch analyzer configuration, and the incremental-ingestion procedure are owned by LinguaBot. The researcher retains the right to use the underlying methods and open-source modules in future academic work.
- Ownership of code: any modifications to the researcher's existing open-source script-normalization modules remain open-source under their existing licence. New integration code written specifically for LinguaBot's pipeline is owned by LinguaBot.
- Data access: LinguaBot transfers data to the researcher under a written data-processing agreement specifying that data are used only for this project, stored on university servers for no longer than six months after project end, and deleted or returned upon request. No raw query or session data may leave the secure analysis environment without written approval from LinguaBot.
- Precondition — data scope: before data transfer, both sides confirm in writing that the dataset contains no personal data of end users (bank or telecoms customers). If any personal data are identified, the data-processing agreement must include GDPR and Serbian personal data protection law (Law on Personal Data Protection, 'Sl. glasnik RS', br. 87/2018) provisions as a precondition to transfer.
- Budget allocation: LinguaBot allocates up to 8,000 EUR for tooling, annotation work by its computational linguists, and direct project costs. The researcher contributes supervision and lab time; no additional fee is proposed beyond this allocation.
- Deliverables and acceptance: the project concludes with a production-ready pipeline, a documented incremental-ingestion procedure, a final evaluation report, and a joint paper draft. Acceptance of deliverables requires written sign-off from both sides within 14 days of delivery.
